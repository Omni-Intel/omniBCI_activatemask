## 源文件防误改

在仓库根目录运行：

```powershell
python products/verify_sources.py
python products/test_verify_sources.py
```

`manifest.json` 记录各冻结文件的 Git blob，以及固件发布文件的源对象 SHA-256。校验包含源提交的文件清单完整性、SHA-256 和工作区未提交的修改，兼容 Git 的 CRLF 换行处理；代码、二进制内容更改或文件缺失会失败。SHA-256 对应 Git 内规范内容，不是 Windows 换行转换后的文本文件字节。需要本地保留三个源提交的 Git 历史；浅克隆应先补全历史并获取 `master`、`esp32-full-diff-v20`、`stm32-compatible` 源分支，CI 已配置完整获取历史。不能只下载 ZIP 后执行此项 Git 来源校验。

肌电软件是允许修改的产品副本，不在冻结清单内；其行为由产品测试覆盖。不要为消除校验失败而直接更新冻结清单，应先确认是否属于经批准的新产品版本。

## 验收顺序

1. 软件检查：冻结源文件完整性、原脑电回归、肌电产品测试、Qt 离线启动与截图。
2. 脑电基线：继续使用原入口及已烧录固件，不为测试肌电覆盖脑电板固件。
3. 肌电实机：与同事验证固件配对，依次验证 250/500/1000 SPS 的设置和读回、断连重连、原始记录时长、滤波/PSD、BDF/FIF 及 SDK 采样率。验证失败时不标为已发布。
4. STM32：本次只确认归档来源和独立启动入口；既有 HEX 不等于本次重编译验证。后续单独推进 Zephyr SD 与外触发，再更新配套 GUI。
5. 用户验收后将集成分支合入 `master`，三产品继续在同一分支的各自目录维护。之后肌电或 STM32 的修改仍不得顺带改动冻结脑电。

离线测试不能证明无线吞吐、真实采样率、模拟前端性能、SD 写入或外触发时序；这些必须由对应硬件测量确认。
