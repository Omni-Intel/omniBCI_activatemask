# 三产品版本与验收入口

本仓库按三套固定硬件/固件/软件配对统一在 `master` 维护，不是万能硬件选择器。代码整合不代表新组合已通过实机验收；稳定脑电继续使用原入口，肌电需组合验收，STM32 仍是后续开发的参考基线。本次不烧录设备。

| --- | --- | --- | --- |

- `1402ec8f9d059afad56e2bfa204743bd90f54ef3` 的原 GUI、固件、依赖和运行启动脚本保持不变。2026-08-31 用户授权修复打包工具及生成物策略，仅对 `.gitignore`、EXE 构建工作流、`build_exe.bat`、`OmniBCI_V19.spec`、`EXE_BUILD_NOTES.txt` 五个文件建立显式例外。
- 肌电固件来自同事验证的 `8779008d749927eb52c2d555221ce319c2047200`，不修改 `.ino`，不复制其通用 GUI 分支的全部修改。
- 肌电软件从稳定脑电软件复制后定向适配；保留实时波形、PSD、滤波、软件触发、通道重命名、原始记录、导出及 SDK 基础能力。
- STM32 参考源码来自 `c2ecbd6423083ae5a196f86d24ce82119ed27752`。本阶段不开发 SD、硬触发或新的业务 GUI；其现有 GUI 不代表已经达到稳定脑电软件的全部功能。
- STM32 采集及控制走 Dongle；原生 USB 只用于升级和调试。缺少 USB 采集控制命令接收不是本次待修复缺陷。

## 源文件防误改

在仓库根目录运行：

```powershell
python products/verify_sources.py
python products/test_verify_sources.py
```

`manifest.json` 记录各冻结文件的 Git blob，以及固件发布文件的源对象 SHA-256。校验包含源提交的文件清单完整性、SHA-256 和工作区未提交的修改，兼容 Git 的 CRLF 换行处理；代码、二进制内容更改或文件缺失会失败。SHA-256 对应 Git 内规范内容，不是 Windows 换行转换后的文本文件字节。

来源提交的历史随本次整合保留在 `master` 的祖先链中，代码内容采用明确选取的产品快照，不用来源分支的旧共享 GUI 覆盖稳定版。只拉取 `master` 的完整历史即可校验，无需日常切换旧产品分支；浅克隆先执行 `git fetch --unshallow origin`。CI 使用完整历史。下载 ZIP 不包含 Git 对象，不能执行此项来源校验。

肌电软件是允许修改的产品副本，不在冻结清单内；其行为由产品测试覆盖。不要为消除校验失败而直接更新冻结清单，应先确认是否属于经批准的新产品版本。

`packaging_overrides` 单独记录上述五个打包文件的新校验值，原始提交的清单和校验值仍然保留。校验器拒绝把 GUI 或固件登记为打包例外。新版根目录 EXE 仍只对应稳定 ESP32 脑电，不打包肌电或 STM32 GUI；构建输出仅保留本地，不上传 Actions 构建附件。

## 验收顺序

1. 软件检查：冻结源文件完整性、原脑电回归、肌电产品测试、Qt 离线启动与截图。
2. 脑电基线：继续使用原入口及已烧录固件，不为测试肌电覆盖脑电板固件。
3. 肌电实机：与同事验证固件配对，依次验证 250/500/1000 SPS 的设置和读回、断连重连、原始记录时长、滤波/PSD、BDF/FIF 及 SDK 采样率。验证失败时不标为已发布。
4. STM32：本次只确认归档来源和独立启动入口；既有 HEX 不等于本次重编译验证。后续单独推进 Zephyr SD 与外触发，再更新配套 GUI。
5. 三产品在 `master` 的各自目录继续维护；发布前按配对关系完成对应实机验收。肌电或 STM32 的修改不得顺带改动冻结脑电；合并到主分支不等同于固件重新验证或正式发布。

离线测试不能证明无线吞吐、真实采样率、模拟前端性能、SD 写入或外触发时序；这些必须由对应硬件测量确认。
