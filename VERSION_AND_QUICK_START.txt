OMNIBCI VERSION AND QUICK START
===============================

Current version
---------------
OmniBCI ADS1299 GUI for fixed-reference V19 and full-differential V20 firmware,
using device-control protocol V1.

Choose the MCU explicitly in the GUI: ESP32-C3 supports USB CDC or BLE;
STM32H563 + E73 uses the USB serial/dongle path.

BLE is considered ready only after the firmware handshake and ADS1299 register
snapshot succeed. Configuration responses use an independent RESPONSE Notify
characteristic and matching request IDs.

GUI
---
First run:  install_and_run.bat
Later runs: run.bat
Main file:  ads1299_eeg_gui_native.py

V19 firmware
-------------
SRB1:
  firmware/ESP32C3_ADS1299_SRB1_BLE_V19/ESP32C3_ADS1299_SRB1_BLE_V19.ino

SRB2 myEMGpcb:
  firmware/ESP32C3_ADS1299_SRB2_DIFF_BLE_V19/ESP32C3_ADS1299_SRB2_DIFF_BLE_V19.ino

V20 full-differential firmware
------------------------------
Each ADS1299 channel samples its own INxP-INxN pair. SRB1 and SRB2 stay off:
  firmware/ESP32C3_ADS1299_FULL_DIFF_BLE_V20/ESP32C3_ADS1299_FULL_DIFF_BLE_V20.ino

For ESP32 direct COM control, build with USB CDC On Boot enabled. The actual COM
number is assigned by Windows and must be selected in the GUI.

The GUI detects V19/V20 from BLE HELLO. V20 also answers the one-byte 0xAB
identity query over USB CDC and reports version, protocol, capabilities and
the full-differential profile.

Dependencies
------------
Core live-acquisition packages are listed in requirements.txt.
Optional BDF/MNE export packages are listed in requirements_optional_export.txt
and can be installed with install_optional_exports.bat.

The optional packages are not required for live USB/BLE acquisition. A missing
pyEDFlib wheel must not block acquisition, filtering, plotting or BIN recording.
