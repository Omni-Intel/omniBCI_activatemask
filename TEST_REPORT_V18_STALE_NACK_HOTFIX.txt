V18 stale-NACK hotfix verification
==================================

Static/Python checks:
- ads1299_eeg_gui_native.py passes python -m py_compile.
- CONTROL packet size/magic/version remain unchanged (18 bytes, BA 43, version 1).
- Firmware STATUS layout remains 72 bytes / protocol V4.
- Both bundled SRB1 and SRB2 V18 firmware contain the same stale-control hardening logic.

Behavioral invariants checked in source:
1. Host NACK is revalidated immediately before its GATT write.
2. Host drops a NACK when the ordered-reassembly hole has already disappeared.
3. Host drops duplicate/older ACK writes already sent on the wire.
4. ACK/NACK use WRITE_NR; RESET continues to use WRITE response.
5. Firmware ignores controls from a previous session without incrementing protocolError.
6. Firmware clips/drops a NACK that is already covered by highest cumulative ACK.
7. Cumulative ACK cancels/trims any already-queued NACK range.
8. Firmware unknownNack increments only for an unacked, already-produced block missing from the retention ring.
9. GUI verdict uses recent STATUS deltas for overflow/unknown/protocol so a historical one-off does not remain the top verdict forever.

Hardware note:
This environment has no ESP32-C3/BLE adapter attached and no Arduino CLI toolchain, so the .ino files were source-checked rather than hardware-compiled/flashed here. Python syntax validation passed.
